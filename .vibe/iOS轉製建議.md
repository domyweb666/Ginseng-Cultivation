# 人蔘修煉 iOS 轉製建議（我的判斷，給你拍板用）

> 這份回答你的第 2、3 題：怎麼轉、該加該砍什麼、怎麼接 iPhone 原生功能。每一條「要／不要」最後都由你決定，進拷問那站時一條條定案。
> 現狀依據：`.vibe/考古版產品定稿.md`、`.vibe/考古版藍圖.md`、`.vibe/意圖落差清單.md`。

## 先講結論

1. 走 SwiftUI 原生重寫，不包殼。
2. 第一版只做三件事：照原樣移植、接「健康」app 讀寫體組成、把慶祝做成真的會震。
3. 你需要一台 Mac。Windows 上我能把整個 Xcode 專案寫到「拿到 Mac 上雙擊就能開、按 Run 就跑」，但編譯、裝到手機、上架這三步只有 macOS 做得到。

## 一、三條路，我選第一條

| | A. SwiftUI 原生重寫 | B. Capacitor 包殼（index.html 原封裝進去） | C. 留在 PWA 補強 |
|---|---|---|---|
| 健康 app 連動 | 直接用 HealthKit | 靠第三方外掛，品質看運氣 | 做不到 |
| 小工具、Siri、觸覺 | 全部能做 | 小工具做不到，觸覺要外掛 | 做不到 |
| 外觀與手感 | 照原本的玉綠、金丹金配色重做，手感是原生的 | 跟現在一樣是網頁 | 跟現在一樣 |
| 要不要 Mac | 要 | 要 | 不用 |
| 工作量 | 原本 615 行邏輯不多，重寫大約十幾個 Swift 檔 | 看起來省，但每個原生功能都在跟外掛打架 | 最省 |
| 我的判斷 | 選這條 | 你要的原生連動它給不全 | 跟你的需求反方向 |

理由只有一個：你要的是「跟手機原生功能連動」，B 和 C 給不了完整的那一種。

技術基線：Swift 5、SwiftUI、SwiftData，最低 iOS 17（iPhone XS 之後的機型都能裝），iPhone 直式為主。

## 二、沒有 Mac 怎麼辦（這題先定，影響我怎麼交付）

| 路 | 做法 | 花費 | 我的看法 |
|---|---|---|---|
| 1. 買一台 Mac | Mac mini 最便宜的那款就夠跑 Xcode | 一次性 | 開發期要反覆真機測手感，這條最順 |
| 2. 租雲端 Mac | MacinCloud、MacStadium 這類，遠端桌面進去用 Xcode | 月費 | 每改一行都要遠端來回，測手感很痛 |
| 3. 雲端自動編譯 | GitHub Actions 的 macOS 機器自動 build，丟 TestFlight 讓你手機裝 | 要 Apple Developer Program（99 美元／年）加簽章設定 | 適合完全不想碰 Xcode 的人，但第一次設憑證還是得借一台 Mac 或找人幫 |

不管哪條，我在 Windows 這邊的交付物一樣：一個完整的 Xcode 專案資料夾，Swift 原始碼、資源、專案檔都齊。

Apple Developer Program（99 美元／年，個人與公司同價）什麼時候才要付：

- 裝到自己手機測試：不用。免費 Apple ID 就能簽，一次 7 天有效，到期重簽。
- HealthKit：不用。Apple 的「Supported capabilities (iOS)」表格裡，HealthKit 在免費的 Apple Developer 欄有勾（2026-11-07 查證）。第一版的健康 app 連動用免費帳號就能在你手機上測。
- 小工具要的 App Groups：不用，同一張表有勾。
- iCloud 同步（CloudKit）：要。免費欄沒勾。
- 推播通知：要。本機通知（每月量測提醒）不算推播，免費就能做。
- TestFlight 給別人測、上架 App Store：要。

## 三、該砍、該留、該強化、該加（我的清單，你勾）

### 砍

| 項目 | 為什麼 |
|---|---|
| claude.ai 資料庫分支、「連線中…／僅存在這台裝置」字樣 | iPhone 上從來沒跑過 |
| 65 kg 預設體重 | 改成「沒量過就先請你量」，或從健康 app 抓 |
| 174 預設身高 | 第一次打開問，或從健康 app 抓 |
| Google Fonts 連線 | 字體打包進 app（LXGW 文楷是開源授權，可以內嵌），離線一樣 |
| 兩段式刪除按鈕 | 換 iOS 慣例：左滑刪除加「復原」 |
| 網頁式日期欄 | 換原生日期選擇器 |

### 不要砍（這 app 的靈魂）

- 全螢幕慶祝與粒子。原生版加上真的震動（Core Haptics），效果比現在好一截。
- 宗門身分、突破紀錄、天梯。這三個是「修仙」成立的地方，拿掉就只是一台 FFMI 計算機。
- 六門功法的名字，和「記最重那組就好」的極簡哲學。

### 強化（原本有，做得更好）

| 項目 | 現在 | 建議 |
|---|---|---|
| 體組成輸入 | 手打體脂秤數字 | 從健康 app 自動帶入最新一筆（Withings、Eufy、小米這類智慧體脂秤多半會寫進健康）。打開錄入頁就填好，按一下結算 |
| 資料安全 | 只在 Safari，清掉就沒了 | SwiftData 本機儲存，加匯出 JSON 備份（分享表單）；有付費帳號再加 iCloud 同步 |
| 存檔失敗 | 被吞掉，畫面照說成功 | 大聲報錯（規矩檔第 4 條） |
| 功法歷史 | 只看最近 20 筆 | 每門功法一條 1RM 走勢線，點進去看全部 |
| 編輯紀錄 | 沒有，只能刪了重記 | 點一筆可改 |
| 體脂超過 20% | 一句「暫不認證」 | 多一句「距根基穩固還差 X%」，給方向 |
| 舊資料 | 留在網頁版的 localStorage | 第一次打開可以匯入網頁版匯出的 JSON（網頁版要先補一個匯出鈕） |

### 加（原本沒有）

| 項目 | 說明 | 我的優先 |
|---|---|---|
| 第一次打開的引導 | 問身高（或抓健康 app）、說明體脂秤怎麼量、什麼時候請你授權健康 | 高。上架必要 |
| 每月量測提醒 | 說明文字已經建議「每月固定一天量」，app 卻沒提醒。本機通知，不用伺服器 | 中 |
| 女性標準表 | 說明寫明「以男性標準設計」。健康 app 可讀性別，切一套女性 FFMI 門檻。數字我不定，要你或查資料 | 只給自己用：低。給粉絲用：高 |
| 一次訓練記多組多動作 | 現在練完一場要按六次。做「這次訓練」容器一次記完，順便有訓練時長 | 中。會動資料模型，第一版可不做，但現在決定最省 |

## 四、跟 iPhone 原生功能連動（分三批）

### 第一批：第一版就做

| 原生功能 | 怎麼用在這個 app | 注意 |
|---|---|---|
| 健康 app 讀取（HealthKit） | 讀體重、體脂率、去脂體重、身高。打開錄入頁自動帶入最新一筆，日期用量測當天 | 要寫授權說明文字；使用者拒絕時 app 要照常能手打 |
| 健康 app 寫入 | 你手打的體重、體脂、去脂體重回寫到健康（可關） | 寫入另外授權 |
| 觸覺回饋 | 煙火時震一下成功型的；記一筆成功輕震 | 取代從沒作用過的 navigator.vibrate |
| 本機儲存 SwiftData | 取代 localStorage | 搭配匯入舊 JSON |
| 匯出備份 | 分享表單存 JSON 到檔案、AirDrop | 免費帳號就能做 |
| 深色模式、動態字體、減少動態效果 | 網頁版都有顧到，原生版照樣 | 上架審核會看 |

### 第二批：第一版穩了再加

| 原生功能 | 怎麼用 |
|---|---|
| 主畫面小工具（WidgetKit） | 一格：目前境界加本週修煉天數；鎖定畫面一格：距下一期還差幾公斤 |
| 捷徑、Siri（App Intents） | 「記一下深蹲 100 公斤 5 下」不用開 app |
| 本機通知 | 每月量測日、連續 N 天沒修煉的溫和提醒 |
| 從健康 app 讀運動 | 有戴 Apple Watch 記「肌力訓練」那天自動算修煉日，沒手記也有天數 |
| iCloud 同步（CloudKit） | 換手機不掉資料。要付費帳號 |

### 第三批：想得到，但先不要

| 原生功能 | 為什麼先不要 |
|---|---|
| 寫運動到健康 app（HKWorkout） | 現在沒記訓練時長，寫一筆假時長進健康 app 是在污染資料。等「這次訓練」容器做了再說 |
| Apple Watch 版 | 另一個 app 的工作量 |
| 即時動態（Live Activity） | 要先有「訓練進行中」的概念 |
| 社群分享卡 | 等粉絲版再說 |

## 五、上架審核會盯的（有 HealthKit 的 app）

- 兩段授權說明文字（讀、寫）要講人話，說清楚拿體重體脂做什麼。
- 健康資料不能拿去做廣告、不能給第三方；隱私營養標籤要勾「健康與健身」。
- 隱私清單檔（PrivacyInfo.xcprivacy）多半要附。
- 使用者拒絕授權，app 不能擺爛，要能手打。

## 六、我預估的切片（給 decompose 那站參考，不是帳本）

1. 規則引擎移植加單元測試（拿現在 app 的數字當標準答案）
2. SwiftData 模型加匯入舊 JSON
3. 錄入頁（三張表單）
4. 境界頁
5. 功法頁
6. 慶祝畫面加觸覺
7. HealthKit 讀寫
8. 匯出備份
9. 第一次打開引導加授權時機
10. 上架前檢核

第 1 片是深模組，要你在線驗。第 3 到 6 片合起來才是「一個端到端玩得到的能力」，攢成一個組塊一起驗。
