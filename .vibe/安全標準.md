## 給 AI 的指令（system instruction）

> 後續寫任何畫面、服務、App Intent、小工具、工作流時，**每寫完一片**必須自查以下清單。
> 找到問題立即修，不要等到上線前才補。
> 三條寫程式時就要守的：健康數值不進 log、不進 URL；量測不進 iCloud；repo 永遠沒有憑證與金鑰。

## 必查清單

### 類別 1：本機儲存（MASVS-STORAGE）

被打中會怎樣：攻擊者拿到手機或備份檔，看到使用者的體重體脂歷史。

- [ ] 量測與修煉存在 app 沙盒的 SwiftData 資料庫，靠系統 Data Protection（預設就有）；不關掉、不改成 NSFileProtectionNone
- [ ] 絕不把體重、體脂率、去脂體重寫進 print、NSLog、os_log；錯誤訊息不夾帶數值（寫「體重超出範圍」，不寫「體重 83.2 超出範圍」）
- [ ] App Group 的小工具快照只放顯示需要的（境界名、期別、本週天數、距下一期差幾 kg），不放原始量測清單
- [ ] 匯出的 JSON 是健康資料：匯出時顯示一句「這個檔案含你的身體數據，自己保管」
- [ ] 不把任何資料放進 URL 或深連結參數；深連結只帶分頁名
- [ ] 截圖防護、退到背景遮蔽：N/A（沒有付款頁；境界畫面本來就是給人截圖的）
- [ ] 存 token、密碼：N/A（沒有帳號）

### 類別 2：加密（MASVS-CRYPTO）

- [ ] 不自己寫加密、不用 MD5、SHA-1；紀錄 id 用系統 UUID；其餘 N/A（資料加密靠系統 Data Protection）

### 類別 3：網路（MASVS-NETWORK）

被打中會怎樣：中間人攔到資料。這個 app 自己不連網，風險主要是「之後有人順手加一個 HTTP 呼叫」。

- [ ] app 自己不發任何 HTTP 請求；唯一對外是 HealthKit、通知、App Store Connect 上傳（CI 端），全部走 Apple 框架
- [ ] 不關 ATS：Info.plist 不出現 NSAllowsArbitraryLoads
- [ ] 隱私政策連結用 https
- [ ] Certificate pinning：N/A（沒有自家伺服器）

### 類別 4：驗證與授權（MASVS-AUTH）

- [ ] N/A：沒有登入、沒有 token。之後若要加帳號，先回來改這份

### 類別 5：平台互動（MASVS-PLATFORM）

被打中會怎樣：別的 app 或惡意連結用深連結、捷徑參數塞怪東西進來。

- [ ] 深連結（通知、小工具、Siri 開 app）只接受固定的分頁名清單，其他一律忽略
- [ ] App Intents 的參數（功法、重量、次數、組數）走跟表單一樣的驗證，不信任 Siri 給的值
- [ ] 沒有 WebView；不註冊 URL scheme；外部檔案只接受匯入，匯入走完整驗證

### 類別 6：程式碼品質（MASVS-CODE）

- [ ] 用最新穩定的 Xcode 與 iOS SDK 建置；最低 iOS 17
- [ ] 零第三方套件（藍圖已定）；之後若要加，先回來改這份並鎖版本
- [ ] Swift 記憶體安全；不用 unsafe 指標、不橋接 C

### 類別 7：抗逆向（MASVS-RESILIENCE）

- [ ] N/A：不碰錢、不含商業機密；不做越獄偵測、不混淆

### 類別 8：隱私（MASVS-PRIVACY 加 App Store 5.1.3）

被打中會怎樣：上架被退、或使用者覺得 app 偷他的健康資料而給一星。

- [ ] HealthKit 只申請四種讀取（體重、體脂率、去脂體重、身高）與三種寫入（體重、體脂率、去脂體重）；不多要
- [ ] 兩段授權說明文字講人話：讀是為了算境界，寫是你自己打開的選項
- [ ] 讀取授權在第一次打開問一次；寫入在使用者打開回寫時才問；拒絕後 app 照常可用
- [ ] PrivacyInfo.xcprivacy：列出用到的「必須說明原因的 API」（UserDefaults 等）與蒐集的資料類型（健康與健身）
- [ ] App Store 隱私標籤：健康與健身資料，「不與使用者身分連結」「不用於追蹤」
- [ ] 健康資料不用於廣告、不給第三方、不做分析（5.1.3 i）；app 裡沒有任何分析或廣告 SDK
- [ ] 不寫假的或推算的數字進 HealthKit（5.1.3 ii）：只回寫使用者手打的三種；去脂體重若是算出來的不寫
- [ ] **不把個人健康資料存進 iCloud（5.1.3 ii）**：量測（體重、體脂率、去脂體重）不進 CloudKit；跨裝置靠健康 app 本身。這條推翻了定稿「iCloud 同步第一版就開」的預設，見 `.vibe/架構藍圖.md` 第八節第 4 點
- [ ] 提供「刪除全部紀錄」：設定裡一鍵刪本機全部資料（含小工具快照）；回寫進健康 app 的由使用者在健康 app 刪，說明寫清楚。定稿沒列、安全標準要求，待你確認
- [ ] 第三方 SDK 的資料蒐集：N/A

### 類別 9：通用 CWE（匯入與 CI）

被打中會怎樣：壞的匯入檔污染資料、憑證外洩讓別人能用你的名義發 app。

- [ ] CWE-20 輸入驗證：表單、Siri、匯入 JSON 三個入口都驗型別與範圍；匯入全驗完才寫，絕不寫一半
- [ ] CWE-502 不安全反序列化：匯入只用 Codable 解 JSON；不用 NSKeyedUnarchiver 解外來檔
- [ ] CWE-22 路徑穿越：匯入只用系統檔案選擇器給的安全範圍 URL；不自己拼路徑
- [ ] CWE-798 硬編碼秘密：repo 永遠沒有 .p12、.p8、密碼；只放 GitHub Secrets；.gitignore 擋 *.p12、*.p8、*.mobileprovision、*.cer
- [ ] CWE-78 指令注入：CI 工作流的 shell 步驟不把任何外部字串（PR 標題、分支名、commit 訊息）拼進指令；secrets 不 echo、不寫進紀錄
- [ ] CI 鑰匙圈：暫時鑰匙圈、隨機密碼、工作結束刪除；工作流只在 main 與自己的分支跑；來自 fork 的 PR 拿不到 secrets（GitHub 預設，不要改）

## 上線前流程

當你說「準備上線了」、「跑安全檢查」時：

1. 觸發 `vibe-security-gate` 階段 C
2. AI 對著這份 `.vibe/安全標準.md` 逐項檢查現有程式碼
3. 產出 `.vibe/安全檢查報告.md`
4. 全綠 → 可上線；有紅 → 必修
