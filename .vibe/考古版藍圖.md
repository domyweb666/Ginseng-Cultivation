## 一、白話走讀（跟著節點編號）

**開 app（n01 → n02 → n03）**：你點開 app，它先畫一次空畫面，然後試著連一個只有在 claude.ai 裡才存在的資料庫。iPhone 上永遠連不到，所以走本機：從 Safari 的 localStorage 把紀錄讀回來，右上角寫「僅存在這台裝置」。n04 那條雲端路是死路，圖上用虛線框。

**三分頁（n05）**：底部「境界／功法／錄入」。每次存檔，三頁一起重畫。

**境界頁（n06 → n07 或 n08）**：沒量過體組成就是「尚未入道」；量過就用最新一筆算 FFMI，顯示境界碑、體脂門檻、三格天數、FFMI 走勢圖、突破紀錄、天梯。

**功法頁（n09）**：六張功法卡各拿你最好的一筆算等級，底下列最近 20 筆。

**錄入頁（n10）**：三張表單（記修煉、量體組成、身高）＋量測紀錄清單。

**記修煉（n11 → n16 → n12 → n19 或 n20）**：存起來，然後比對存之前的狀態，決定放煙火（宗門晉升／功法突破／功法精進）還是小提示（開練／+1）。

**量體組成（n13 → n16 → n14 → n19 或 n20）**：存起來、跳到境界頁，決定放煙火（踏入仙途／境界突破／大境界突破）還是小提示（暫不認證／結算）。

**身高（n15）**：存一個數字，但整條歷史跟著重算。

**刪除（n18 → n16）**：按兩下才刪，刪了沒得復原。

**規則引擎（n21）**：三張門檻表＋全部公式。整個 app 對不對都看它。

這段白話是你要確認的東西，圖只是輔助。看到跟你認知不一樣的，直接說。

## 二、標註

### ⚠️ 危險方塊（碰資料、刪東西、對外連線）

| 節點 | 為什麼危險 | 轉 iOS 時 |
|---|---|---|
| n16 寫入儲存 | 全世界只有這一份資料，沒備份、沒匯出；寫入失敗會被吞掉 | 換 SwiftData，加匯出備份，錯誤要大聲報 |
| n18 刪除 | 兩段式確認但無復原 | 改 iOS 慣例（滑動刪除＋可復原），或加確認 |
| n15 身高 | 一改全部歷史重算，使用者不一定知道 | 保留行為，但改的時候講清楚 |
| n04 雲端監聽 | 唯一的對外連線，而且 iPhone 上走不到 | 整段刪掉 |
| （沒有） | 沒有金流、沒有登入、沒有寄訊息、沒有第三方 API | 守門目前不用擋什麼 |

### 🔁 重複疑點

- 「去脂體重 ＝ lean 或 體重×(1−體脂率)」：L231 有 leanOf()，但 renderRealm、chart、fillHistory 裡又各自手算一次。
- 「今天的日期字串」：L267 today() 和 L327 weekCount() 各組一次。
- 「存之前記狀態、存之後比較、決定煙火或提示」：onLift 和 onMeas 各手刻一套，邏輯平行但沒共用。
- put／del 各有 LOCAL 與 DB 兩套分支，DB 那套在 iPhone 上永遠不跑。

### 🎨 風格漂移

- 單一作者、單一檔案，風格一致，沒有漂移。CSS 分兩段（head 一段基礎、body 一段主樣式），小事。
- 變數名極短（m、l、R、S、bt、nr），人讀得辛苦但機器沒差。轉 Swift 時要翻成讀得懂的名字，這是 voice-lock 那站要立的規矩。

### 🧠 深模組（刪除測試）

| 方塊 | 刪掉攤平會怎樣 | 判定 |
|---|---|---|
| n21 規則引擎 | 境界、功法、宗門、突破全部要在每個畫面各算一遍，複雜度集中爆炸 | 真深模組。轉 iOS 第一片就先移植它，配單元測試，拿現在 app 的輸出當標準答案 |
| n12／n14 慶祝判定 | 搬到畫面層也只是搬位置 | 淺模組。但它決定「什麼時候放煙火」，這是 app 的靈魂，要列黃金行為 |
| n19 慶祝畫面 | 純呈現 | 淺 |
| 其他畫面 | 純呈現 | 淺 |

### 🔗 哪些方塊互相獨立（給之後平行判斷用）

- 境界頁（n06–n08）、功法頁（n09）、錄入頁（n10）彼此獨立，都只依賴 n21 與 state。
- 慶祝畫面（n19）與 toast（n20）獨立於所有頁面。
- 規則引擎（n21）被四處依賴，動它要全部重驗。

### 🕳️ AI 讀不懂／沒把握的角落（請你用實際操作驗）

1. **客卿／執事的例外身分**：程式邏輯我讀得懂（元嬰以上但天數不到長老門檻 → 客卿長老；金丹以上但不到真傳 → 客卿；天數 ≥100 且超過下一階天數門檻但境界不夠 → 執事）。這是不是你的本意、邊界對不對，我驗不了。
2. **FFMI 低於 16.5**：會顯示「煉氣初期」、進度條 2%、「距煉氣初期還差 X kg 肌肉」。你人在煉氣初期，它卻說還差，文字矛盾。要不要有「未入門」這一階？
3. **門檻數字來源**：七境界的 FFMI 區間、六功法的五階比值、宗門天數門檻，看起來像常見的 FFMI 分級與力量標準表，但我不知道你從哪抄的、要不要調。
4. **引體向上的「下一階約 N 下」**用 (門檻−1)×30 反推次數，是 Epley 公式倒算，粗略。
5. **本週修煉週一起算**；「入道（天）」從第一次有效量測算到今天。對不對看你。
6. **同一天量兩次體組成會蓋掉**；同一天記兩筆同功法修煉會各存一筆。
7. **沒量測就記修煉，體重用 65 kg 算**：看起來是暫時填充，但它會真的影響功法等級顯示。
8. **存檔失敗被吞掉**：localStorage 寫不進去（滿了、私密瀏覽）時畫面照樣顯示「已記下」。實際多常發生我不知道。
9. **加到主畫面的網站資料會不會被 iOS 自動清**：一般 Safari 網站 7 天沒互動可能被清，主畫面 app 據說豁免，我沒把握。
10. **沒有 service worker**，離線打開能不能成功，我在 Windows 上驗不了。
11. **右上角「連線中…」**一瞬間變「僅存在這台裝置」，是殘留；你有沒有注意過。
