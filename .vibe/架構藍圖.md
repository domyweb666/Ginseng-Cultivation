## 一、白話走讀：app 怎麼跑（a01 到 a21）

**第一次打開（a01 → a02 → a03）**：app 起來先建資料庫（本機）。設定裡沒有身高就是第一次。這時跳出整個 app 唯一一次主動的系統視窗：健康 app 的讀取授權，一次問四種（身高、體重、體脂率、去脂體重）。你允許而且健康 app 裡有身高，連身高都不問，直接進境界頁；不允許或沒有，就出現一個身高欄，填完進去。沒有教學頁。

**三分頁（a03）**：境界、功法、錄入。預設停在境界。

**境界頁（a04）**：沒量過就是雜役服人蔘加一句「去量一次體脂秤」。量過就是宗門身分卡、境界碑、三格天數、FFMI 走勢、突破紀錄、天梯、說明。體脂超過 20% 的人也看得到自己的境界，但境界碑標「根基不穩」、進度條灰掉、多一句「降到 20% 以下才生效，還差 Y%」。

**功法頁（a05）**：六張功法卡加最近修煉；點一張卡進去看那門功法全部紀錄和 1RM 走勢線。

**錄入頁（a06）**：最上面是「今天的修煉」清單加四欄表單，記完一筆重量清空、其他留著，連著記不用跳。中間是量體組成：一進頁就去健康 app 拿最新一筆體重、體脂率、去脂體重填好，標來源和日期；拿不到就留白讓你手打。下面是設定入口。

**記修煉（a08 → a10 → a11 → a13）**：驗四欄 → 存 → 用規則引擎比存前存後，五選一：宗門晉升、開練、功法突破、功法精進、+1。前三個放煙火加震動（a13），後兩個是頁內小提示。精進只在 1RM 真的變高才放；體重掉讓比值變高的不放。

**量體組成（a09 → a10 → a12 → a13 或 a04）**：驗三欄；同一天已有一筆先問要不要蓋 → 存 → 四選一：根基不穩（顯示但不算突破）、踏入仙途、境界突破或大境界突破、結算。放煙火或直接切到境界頁。回寫健康 app 開著而且數字是手打的，順便寫進健康 app。

**儲存（a10）**：寫本機資料庫；成功就更新小工具的快照並叫它刷新；失敗把錯誤丟回表單紅字顯示，絕不說「已記下」（a21）。

**改和刪（a14）**：左滑刪除，底部「復原」5 秒；點一筆進編輯。

**設定（a15 → a16）**：身高、回寫健康 app 開關（打開那一刻才問寫入授權）、每月提醒、匯出 JSON、匯入舊 JSON（先驗格式、預覽筆數、確認才寫，壞檔拒絕）、授權狀態、隱私政策。

**Siri（a17）**：「記一下深蹲 100 公斤 5 下」不開 app 直接存，回一句話；「我現在什麼境界」回一句。

**小工具（a18）**：讀主 app 存的快照：小的顯示境界和本週天數，中的多一句差幾公斤，鎖定畫面一個圓形顯示本週天數。

**規則引擎（a20）**：三張表加全部公式，原樣從 index.html 搬，做成獨立的純 Swift 套件，單元測試拿網頁版真實資料當標準答案。境界頁、功法頁、兩個判定、Siri、小工具快照全部呼叫它，沒有第二份算法。

**你看這條線對不對？**特別看三個地方：(1) 第一次打開只跳一次健康授權、最多問一個身高；(2) 體脂超標的人看得到境界但不算突破；(3) 記修煉的煙火規則。

## 二、白話走讀：程式怎麼變成你手機上的 app（d01 到 d12）

你手上沒有 Mac，所以這條線要先講清楚。我在這台 Windows 上寫好整個 Xcode 專案和自動編譯的設定檔，推上 GitHub（d01）。GitHub 自動開一台 Linux 機器跑規則引擎的測試（d03），綠了才開一台 macOS 機器（d04 到 d06）：還原你的發佈憑證、用 Xcode 建置、直接上傳到 App Store Connect。十幾分鐘後你手機的 TestFlight 跳出新版本，裝了就能照 PRD 的完成定義親手驗（d07）。任何一步紅燈（d08），我讀建置紀錄、修、再推，第一次編譯幾乎一定會紅幾輪，這是正常循環。

這條線跑起來之前要先做一次憑證（d11）：在 Windows 上用 openssl 產金鑰和申請檔、到 Apple 開發者後台簽、合成 .p12、放進 GitHub 的 Secrets；再到 App Store Connect 建一把 API 金鑰也放進去。這一段我會寫成一步一步的操作說明給你照做，大約半小時，一年做一次。

上架（d10 → d12）是最後：建 app 記錄、隱私政策頁、截圖、說明、隱私標籤，挑一個 TestFlight 版本送審。

網頁版補一顆「匯出 JSON」鈕（d09），你在 iPhone Safari 按一下存到檔案 app，再到 iOS 版設定裡匯入，舊紀錄就過來了。

## 四、資料模型

| 模型 | 欄位 | 備註 |
|---|---|---|
| Measurement | id（UUID）、date（日期，到日）、weight（kg）、bodyFat（%）、leanMass（kg，可空）、source（manual 或 health）、importKey（網頁版 id，可空）、createdAt | 同一天只准一筆，由 StoreService 擋。從健康 app 重建時 importKey 放 HealthKit 樣本的 UUID，去重用 |
| LiftRecord | id、date、move（squat／dead／bench／ohp／row／pull）、kg、reps、sets、bodyweight（當天體重快照，可空）、source、importKey、createdAt | 跟網頁版一筆一筆對應 |
| UserSettings | height（可空）、healthWriteEnabled（預設關） | 一筆，本機 |
| 本機偏好（不同步） | reminderEnabled、reminderDay | 提醒是每台裝置各自的 |
| 小工具快照（App Group） | realmName、stageName、weekDays、kgToNext、updatedAt | 主 app 每次存檔後寫 |

不做 iCloud（審核規範 5.1.3，第八節第 4 點），模型不受 CloudKit 限制；每個欄位仍給預設值，方便匯入與之後的版本升級。

網頁版 JSON（匯入匯出同一格式）：`{ meas:[{id,date,weight,bf,lean?,t}], lift:[{id,date,move,kg,reps,sets,bw,t}], cfg:{height} }`。對應：bf → bodyFat、lean → leanMass、bw → bodyweight、t（毫秒）→ createdAt、id → importKey（去重用）。

## 五、規則引擎介面（跟網頁版一對一）

| 網頁版 | RencanCore | 說明 |

| ffmi(lean,hcm)、leanFor(f,hcm) | ffmi、leanFor | 身高校正公式 |
| realmOf(f) | realmOf | 回境界、期別、下一期門檻、起點 |
| e1rm(load,reps)、moveLevel(m,ratio) | e1rm、moveLevel | Epley、五階門檻 |

| bwAt、liftCalc、bestByMove、trainDays、weekCount、durTxt、daysBetween | 同名 | bwAt 沒量測時回 nil，不再預設 65 |

輸入輸出都是純值；沒有 UI、沒有資料庫。bwAt 回 nil 時，呼叫端要先請使用者量體重才算功法（PRD：體脂數字必要，體重也一樣）。

### 🔗 互相獨立的方塊（給平行判斷用）

- 境界頁、功法頁、錄入頁三個畫面彼此獨立，都只依賴規則引擎與 StoreService 的介面。
- 小工具只依賴快照格式；Siri 只依賴 StoreService 與規則引擎。
- CI 管線與 app 程式碼獨立（只要專案檔存在就能跑）。
- 網頁版匯出鈕跟 iOS 完全獨立。
- 規則引擎被所有人依賴，動它要全部重驗。

三張表與公式數字、立繪、配色、Apple 原生框架；不裝第三方套件。

## 八、對定稿預設的調整（2026-11-07 你已點頭，五項全部套用到定稿、PRD、流程圖）

1. **健康 app 讀取授權時機**：定稿寫「第一次進錄入頁時問」。藍圖改成「第一次打開時一次問四種」，因為首次要抓身高本來就得問，拆成兩次會多跳一個視窗，違反「引導越少越好」。寫入授權不變，設定打開回寫時才問。
2. **每月提醒不跟著 iCloud 同步**：提醒是每台裝置各自設定。
3. **bwAt 不再預設 65 kg**：沒量過體重就不算功法等級，功法卡顯示「先量一次體重」。這是定稿「砍 65 kg 預設」的直接結果。
4. **iCloud 同步改為不做**（推翻定稿「第一版就開」的預設）：App Store 審核規範 5.1.3(ii) 寫明健康類 app「不得把個人健康資料存在 iCloud」，這條從 2014 年 HealthKit 推出就有；我們讀 HealthKit 又把體重體脂同步進 CloudKit，退件風險真實存在（2026-11-07 查證；論壇上「自家 CloudKit 私有資料庫算不算」沒有 Apple 正式答覆）。改法：量測不進 iCloud，換手機時從健康 app 重建（體脂秤來源或開了回寫的都在健康 app 裡）；修煉紀錄與身高用匯出匯入帶過去。你點頭後我改 PRD 的 S21、定稿預設、流程圖的 a10，並刪掉第四節的 iCloud 三條限制。好處：少一個深模組，資料模型不受 iCloud 限制。
5. **設定加「刪除全部紀錄」**：安全標準（MASVS-PRIVACY）要求能一鍵刪掉自己的資料；定稿沒列。只刪本機與小工具快照，回寫進健康 app 的由使用者在健康 app 刪，說明寫清楚。
