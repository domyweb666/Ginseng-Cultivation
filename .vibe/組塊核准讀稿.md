# 組塊核准讀稿（動工前的批量核准）

> 這份是給你看「每一塊要做什麼、怎麼組」，不是驗「做得對不對」。你放行哪一塊，我才動那一塊。
> 一共 10 個組塊、36 片。順序：A → B → C → D → E → F → G → H → I → J。每塊到齊就出一個 TestFlight 版本給你玩，一次驗整塊；標「立即驗」的片做完當下就攔你驗，不等整塊。
> 對應帳本：`.vibe/切片帳本.md`。

## 組塊 A：裝得到你手機上（交付骨架）

**一句話**：做完這塊，你手機的 TestFlight 裡有一個會開的「人蔘修煉」，三個分頁是空的，但從我推程式碼到你裝上這條路已經通了。

**由這幾片組成**：
- 片 A1：憑證與金鑰。你照我寫的說明在 Windows 做一次，把「你的 Apple 身分」放進 GitHub 的保險箱。比喻：去郵局辦一個印章和存摺，之後寄任何東西都靠它。｜**立即驗**（憑證）
- 片 A2（walking skeleton）：Xcode 專案骨架，三個空分頁、顏色、字體、立繪先放好。比喻：先把房子的地基、樑柱、水管接到尾，還沒裝家具，先確認水會流。｜**立即驗**（骨架）
- 片 A3：GitHub Actions 工作流，我推程式碼，GitHub 的機器自動測、自動建、自動上傳。比喻：裝一條自動生產線，之後每次改都是按同一顆鈕。｜**立即驗**（碰保險箱、對外上傳）
- 片 A4：TestFlight 首次安裝。比喻：生產線第一個成品送到你門口。｜**立即驗**（骨架）

**這幾片怎麼組**：A1 是前提，沒印章寄不出去。A2 跟 A1 互不相干，可以同時做。A3 要 A1、A2 都好。A4 是 A3 的結果。

**我會怎麼做這塊**：A1 我給你一份操作說明，你做，大約半小時。同時我做 A2。A3 我寫完推上去，紅燈我讀紀錄修到綠；第一次編譯幾乎一定紅幾輪，這是正常。綠了你裝 A4。這塊幾乎每片都要你在線。

## 組塊 B：規則引擎（🧠 深模組）

**一句話**：做完這塊，境界、功法、宗門、突破的算法全部搬到 Swift，而且有機器每次都檢查它跟網頁版算得一模一樣。

**由這幾片組成**：
- 片 B1：三張表與全部公式原樣搬。比喻：把你的食譜從手寫本抄成印刷版，一個字都不准改。｜**立即驗**（深模組）
- 片 B2：黃金集。我用電腦跑原版網頁的算法，算一批題目的標準答案存起來；Swift 版每次都要考同一份考卷。比喻：影印一份標準答案，新廚師每次出菜都要跟它對味。｜**立即驗**
- 片 B3：判定，也就是什麼時候放煙火，含三條新規則。比喻：裁判手冊，每一條規則配一個測試案例。｜**立即驗**
- 片 B4：網頁版 JSON 的格式定義與驗證。比喻：規定「食材進貨單」長什麼樣，不合格的退貨。｜可批次

**這幾片怎麼組**：B1 是根，B2 考 B1，B3 用 B1，B4 獨立。B1 → B2 → B3 依序；B4 可以跟 B3 同時。

**我會怎麼做這塊**：全部在 GitHub 的 Linux 測試機上驗，你看綠燈，測試名都是中文句子。這塊你驗不了細節，是信任機器的地方，所以 B3 的規則我會先用白話列給你看過。真正拿數字對網頁版，在組塊 C、D 的畫面上做。

## 組塊 C：記修煉

**一句話**：做完這塊，你能在手機上記修煉、看功法卡、改和刪，數字跟網頁版一樣。

**由這幾片組成**：
- 片 C1（walking skeleton）：資料模型與儲存服務。比喻：先做櫃子和抽屜，東西才有地方放。｜**立即驗**（骨架）
- 片 C2：錄入頁上半，今天的修煉清單加四欄表單。比喻：登記簿，今天的在最上面。｜可批次
- 片 C3：功法頁，六張卡加單一功法走勢。比喻：成績單。｜可批次
- 片 C4：判定接上畫面，先用小提示。比喻：先口頭宣布得獎，獎盃組塊 D 再給。｜可批次
- 片 C5：編輯與刪除。比喻：橡皮擦，擦了 5 秒內可以反悔。｜**立即驗**（刪資料）

**這幾片怎麼組**：C1 是地基。C2、C3 互不相干，可以同時做。C4 要 C2、C3。C5 要 C2。

**我會怎麼做這塊**：C1 做完推一版，你只看得到開得起來。C2、C3 同時做，C4、C5 接著。整塊到齊出 TestFlight 版，你用網頁版同樣的幾筆資料記進去對數字。

## 組塊 D：境界那一刻（核心）

**一句話**：做完這塊，你量一次體組成就看到境界、煙火、震動。這是整個 app 的那一刻。

**由這幾片組成**：
- 片 D1（walking skeleton）：首次問身高（手填）、體組成表單、四選一判定。比喻：體重計裝好、刻度校正。｜**立即驗**（骨架）
- 片 D2：境界頁，境界碑、宗門卡、三格、天梯、說明。比喻：成績公佈欄。｜可批次
- 片 D3：走勢圖與突破紀錄。比喻：成長紀錄本。｜可批次
- 片 D4：慶祝畫面、粒子、震動，接上所有煙火。比喻：頒獎典禮，連修煉那邊的得獎也在這裡頒。｜**立即驗**（靈魂、手感）

**這幾片怎麼組**：D1 地基。D2、D3 互不相干，可以同時做。D4 要 D1 和組塊 C 的判定。

**我會怎麼做這塊**：D1 先；D2、D3 同時；D4 最後。手感要你真機感受，震動強度、粒子多少可能來回兩三版。

## 組塊 E：健康 app 連動

**一句話**：做完這塊，體脂秤的數字自動出現在錄入頁，你手打的也能回寫，換手機能從健康 app 把量測找回來。

**由這幾片組成**：
- 片 E1：健康 app 服務，授權、查最新、查歷史、寫入。比喻：跟健康 app 之間裝一扇門和門禁。｜**立即驗**（對外系統）
- 片 E2：首次抓身高、錄入頁自動帶入。比喻：門裝好了，東西自動送進來。｜可批次
- 片 E3：回寫設定，預設關。比喻：另一扇往外的門，你自己決定開不開。｜**立即驗**（寫系統健康資料）
- 片 E4：從健康 app 重建歷史。比喻：搬家時把舊照片從雲端相簿抓回來。｜**立即驗**（合併規則）

**這幾片怎麼組**：E1 是門，其他三片都靠它。E2、E3、E4 互不相干，可以同時做。

**我會怎麼做這塊**：E1 先，三片同時，整塊出一版。驗的時候你需要一台會連健康 app 的體脂秤，或在健康 app 手動加一筆。

- 片 F3：匯入，驗、預覽、確認、寫入。比喻：搬家公司進門前先清點清單，有壞的整車退回，不搬一半。｜**立即驗**（大量寫入）

**這幾片怎麼組**：F1 獨立，可以最早做。F2、F3 共用組塊 B 的格式定義。F4 獨立。

**我會怎麼做這塊**：F1 先做，你馬上在 Safari 驗。F2、F3、F4 可以同時。整塊出一版，你把真實資料匯進來對照。
