## 第 4 題：訓練資料模型的三個選項（已定：丙）

| | 甲、維持單筆（現狀） | 乙、改成「一次訓練」 | 丙、單筆加「今天的修煉」清單（我推薦） |
|---|---|---|---|
| 一筆是什麼 | 一個動作的最重那一組：重量、次數、組數、日期 | 一場訓練：開始、結束，裡面多個動作，每個動作多組（每組重量×次數） | 跟甲一樣是單筆，但錄入頁按日期分組顯示 |
| 練完一場怎麼記 | 四個動作按四次「記下這一練」，每次回到表單重選 | 按「開始訓練」，一組一組記，按「結束」 | 四個動作在同一頁連著記，不用跳來跳去 |
| app 多知道什麼 | 沒有 | 練了多久、總訓練量、每組細節 | 沒有（跟甲同） |
| 能多做什麼 | 沒有 | 寫一筆有真實時長的「肌力訓練」進健康 app；即時動態「訓練進行中」；總量走勢 | 沒有，但之後要升級成乙時，同一天的單筆可以直接包成一場，不用砍掉重練 |
| 代價 | 錄入要按很多次 | 資料結構變三層；多一個「進行中」狀態；每組都要記，極簡感消失；Siri 還要多「開始、結束」指令 | 只改錄入頁的排版，資料不動 |
| 境界與功法算法 | 不變 | 不變（還是看最重那組的 1RM ÷ 體重） | 不變 |
| Siri 一句話記一筆 | 剛好 | 一句記一組，但要先開始訓練 | 剛好 |
| 舊資料匯入 | 一對一 | 要把舊單筆硬包成訓練，沒有時長 | 一對一 |

我推薦丙：第一版範圍已經很大（HealthKit、小工具、Siri 三個原生功能），不再動資料模型；錄入體驗的痛點（按很多次）用排版解掉；之後真的想要時長再升級成乙，路沒堵死。

## 我的預設（技術題，你沒意見就這樣走）

| 項目 | 預設 | 理由 |
|---|---|---|
| 最低 iOS | 17 | SwiftData 需要；iPhone XS 之後都能裝 |
| 語言 | 繁體中文（台灣） | 先做你會的；英文等有需求再開 |
| App 名稱 | 人蔘修煉 | 沿用 |
| Bundle ID | org.domyweb.rencan | 你的網域反過來寫。上架後改不了，要改趁現在 |
| iCloud 同步 | 第一版就開（CloudKit 私有資料庫） | 給別人用，換手機不掉資料是基本。它限制資料模型怎麼寫，所以要在寫模型前定 |
| 健康 app 寫入 | 預設關，設定裡開 | 給別人用，有人不想 app 動他的健康資料。讀取在引導時請求 |
| 小工具 | 主畫面小（境界加本週天數）、主畫面中（再加距下一期差幾公斤）、鎖定畫面圓形（本週天數） | 先做三種，其餘看回饋 |
| Siri、捷徑 | 「記一下〔功法〕〔重量〕公斤〔次數〕下」、「我現在什麼境界」 | 兩個最常用的 |
| 舊資料匯入 | 網頁版補一個「匯出 JSON」鈕，iOS 第一次打開可以匯入 | 你自己的紀錄不能丟 |
| 隱私政策 | 放在 domyweb.org 一頁 | 上架必填，有 HealthKit 的 app 一定要有 |
| 收費 | 免費，無內購 | 第一版先看留存；內購之後另開切片 |
| CI 簽章 | 憑證在 Windows 用 openssl 做 CSR、Apple 後台簽、.p12 進 GitHub Secrets；上傳用 xcodebuild 直傳 App Store Connect | 整條路不需要 Mac |
