## 1. 問題陳述與解決方案

- **解決誰的什麼問題**：有在重訓的人，包含剛開始的新手，看不到自己「有沒有變強」。體脂秤的數字和槓鈴上的重量都是冷的，練三個月感覺沒差就放棄。現在的網頁版「人蔘修煉」已經把這些數字翻成修仙境界和功法，但它困在 Safari 裡：資料清掉就沒了、體脂秤的數字要手打、慶祝不會震、沒有東西提醒他回來量。
- **我們打算怎麼解**：把網頁版搬成原生 iPhone app，境界、功法、宗門的算法一字不改，但把「量完看到境界」那一刻做順做爽：體脂秤的數字從健康 app 自動帶進來、慶祝會震、境界住在主畫面小工具上、一句話跟 Siri 記修煉、換手機舊紀錄帶得走（量測靠健康 app，其餘靠匯出匯入；不走 iCloud，審核規範不准）。不加欄位、不加引導、不做課表。北極星：陌生人裝了三個月後還在量。

## 2. 使用者故事（每條附完成定義）

### 境界那一刻（核心）

- **S1** 身為剛裝 app 的人，我想要第一次打開最多只被問身高，這樣我就能馬上開始用。
  - 完成定義：全新安裝打開 → 如果健康 app 有身高而且我允許讀取，直接進境界頁；否則只出現一個身高欄，填完進境界頁。中間沒有任何教學頁或輪播。
- **S2** 身為有智慧體脂秤的人，我想要打開錄入頁時體重、體脂率、去脂體重已經填好，這樣我就只要按一下「結算境界」。
  - 完成定義：體脂秤今早把數字同步進健康 app → 我打開錄入頁 → 三個欄位顯示今早的數字和日期 → 按「結算境界」就看到境界。
- **S3** 身為沒有智慧體脂秤的人，我想要手打體重和體脂率就能結算，這樣我就不被健康 app 綁住。
  - 完成定義：拒絕健康 app 授權 → 錄入頁仍能手填體重、體脂率（去脂選填）→ 結算 → 看到境界。沒有體脂率不能送出。
- **S4** 身為量完的人，我想要馬上看到境界、期別、FFMI、還差多少肌肉升下一期，這樣我就知道自己在哪。
  - 完成定義：結算後境界頁顯示境界名、期別、FFMI（小數兩位）、去脂體重、「距〔下一期〕還差肌肉 X kg」；同一筆資料在網頁版算出來的數字一模一樣。
- **S5** 身為第一次有效量測的人，我想要看到「踏入仙途」的全螢幕慶祝而且手機會震，這樣那一刻才有感。
  - 完成定義：第一筆體脂率 20% 以下的量測結算 → 全螢幕慶祝（立繪、粒子、大字）、手機震一下 → 點一下或 4.5 秒後關閉。系統開「減少動態效果」時不噴粒子但仍顯示。
- **S6** 身為突破到新期別的人，我想要看到「境界突破」，跨大境界時看到「大境界突破」。
  - 完成定義：新量測的期別高於歷史最高、日期不早於上次突破 → 慶祝；補登過去日期的量測 → 只有小提示，不進突破紀錄。
- **S7** 身為體脂超過 20% 的新手，我想要仍然看到算出來的境界，但知道它還不算數、還差多少，這樣我就不會覺得被拒絕。
  - 完成定義：體脂 24% 結算 → 境界碑顯示境界與期別，但標「根基不穩」、進度條灰掉、文字「降到 20% 以下境界才生效，還差 4%」；突破紀錄和宗門身分不因這筆改變。
- **S8** 身為持續量的人，我想要看到 FFMI 走勢圖、突破紀錄、天梯，這樣我就看得到自己在往上爬。
  - 完成定義：兩筆以上量測 → 走勢圖出現，境界門檻畫成金色虛線；突破紀錄列出每個第一次到達的期別、日期、距上一階多久；天梯在目前境界打金框。一筆時只顯示一句話。
- **S9** 身為同一天量兩次的人，我想要被問要不要蓋掉早上那筆，這樣我就不會不小心弄丟。
  - 完成定義：同一天第二次結算 → 跳出「今天已經有一筆，要蓋掉嗎」→ 確認才蓋。

### 記修煉（習慣線）

- **S10** 身為練完的人，我想要在同一頁連著記四個動作，每個只填功法、重量、次數、組數，這樣我就不用來回跳。
  - 完成定義：錄入頁最上面是「今天的修煉」清單 → 記完深蹲，表單留在原位、重量清空、功法可直接換 → 再記臥推 → 清單出現兩筆，按日期分組。欄位只有功法、重量、次數、組數、日期，沒有第六個。
- **S11** 身為引體向上的人，我想要徒手填 0、加重才填數字，這樣我就不用算自己體重。
  - 完成定義：選攀雲梯 → 欄位名變「加重 kg」、可留空 → 等級用體重加加重算。
- **S12** 身為破紀錄的人，我想要只有真的更重時才放「功法精進」的煙火。
  - 完成定義：估計 1RM 比上次最佳高 → 慶祝，寫出多了幾公斤；體重掉了、1RM 沒變（比值變高）→ 等級可能升，但不放精進煙火。
- **S13** 身為升等的人，我想要看到「功法突破」。
  - 完成定義：比值跨過門檻 → 全螢幕慶祝顯示新等級名與功法名。
- **S14** 身為修煉天數到門檻的人，我想要看到「宗門晉升」。
  - 完成定義：記下一筆讓累計天數達到外門門檻（8 天）→ 全螢幕宗門晉升、長老圖；同一天記第二筆不重複算天。
- **S15** 身為記錯的人，我想要能改也能刪，刪錯還能救回。
  - 完成定義：清單左滑刪除 → 底部出現「復原」幾秒；點一筆 → 可改重量、次數、組數、日期 → 存回 → 功法等級跟著重算。
- **S16** 身為看功法頁的人，我想要看到六門功法的等級、進度、下一階要多少，和每門功法的 1RM 走勢。
  - 完成定義：六張卡數字跟網頁版一樣；點一張卡 → 這門功法所有紀錄和 1RM 走勢線。

### Siri 與小工具

- **S17** 身為懶得開 app 的人，我想要對 Siri 說「記一下深蹲 100 公斤 5 下」就記好。
  - 完成定義：對 Siri 或捷徑說那句 → 回「已記下坐馬樁，修煉 +1」→ 打開 app，清單裡有這筆（組數沒講就記 1 組，講「3 組」就記 3）。六門功法的中文名和功法名都聽得懂。
- **S18** 身為想知道境界的人，我想要問 Siri「我現在什麼境界」。
  - 完成定義：Siri 回「金丹中期，距後期還差 1.2 公斤肌肉」；沒量過回「尚未入道，先量一次體組成」。
- **S19** 身為裝了小工具的人，我想要主畫面看到境界和本週修煉天數，記完馬上更新。
  - 完成定義：加小尺寸小工具 → 顯示境界、期別、本週天數；中尺寸再多「距下一期還差 X kg」；記一筆或結算後回主畫面，小工具已更新。
- **S20** 身為看鎖定畫面的人，我想要一眼看到本週修煉天數。
  - 完成定義：加鎖定畫面圓形小工具 → 顯示本週天數。

### 資料不掉

- **S21** 身為換手機的人，我想要舊紀錄能帶到新手機。
  - 完成定義：新手機裝 app 並允許讀健康 app → 量測紀錄（來自體脂秤、或舊手機開了回寫的）自動重建，境界與突破紀錄算出來跟舊手機一樣；修煉紀錄與身高用舊手機匯出的 JSON 匯入後一筆不少。不走 iCloud（審核規範 5.1.3 不准把健康資料存 iCloud）。
- **S22** 身為網頁版老用戶，我想要把舊紀錄搬進來。
  - 完成定義：網頁版按「匯出」存 JSON → iOS 設定「匯入」選那個檔 → 量測、修煉、身高一筆不少；突破紀錄和天數算出來跟網頁版一樣。
- **S23** 身為謹慎的人，我想要隨時匯出備份。
  - 完成定義：設定「匯出 JSON」→ 分享表單 → 存到檔案或 AirDrop。
- **S24** 身為存檔失敗的人，我想要被告知，不要假裝成功。
  - 完成定義：寫入失敗 → 紅色錯誤，表單內容留著；絕不顯示「已記下」。
- **S28** 身為想重來或要清掉資料的人，我想要一鍵刪掉 app 裡全部紀錄。
  - 完成定義：設定「刪除全部紀錄」→ 確認 → 境界頁回到尚未入道、功法頁全部未入門、小工具顯示尚未入道；健康 app 裡的資料不受影響，畫面有寫明。

### 健康 app 與提醒

- **S25** 身為想讓健康 app 也有紀錄的人，我想要在設定打開回寫，而且預設是關的。
  - 完成定義：設定打開「回寫健康 app」→ 此時才請求寫入授權 → 之後手打的體重、體脂率、去脂體重出現在健康 app；從健康 app 帶入的不重複寫回去。
- **S26** 身為會忘記量的人，我想要每月固定那天早上被提醒。
  - 完成定義：設定開啟提醒、選日子 → 那天早上收到通知「該量一次了」→ 點通知直接進錄入頁。

### 上架

- **S27** 身為陌生人，我想要在 App Store 搜到「人蔘修煉」、裝了就能用。
  - 完成定義：App Store 上架頁有截圖、說明、隱私標籤、隱私政策連結；審核通過；裝了走 S1。

## 3. 實作決策

- **大概會動到的塊（白話）**：
  1. 規則引擎：境界、功法、宗門、突破的公式與三張表。原樣移植。
  2. 資料層：本機儲存、匯入舊 JSON、從健康 app 重建量測、匯出備份、同日覆寫詢問、刪除全部紀錄。
  3. 健康 app 連接層：讀四種（體重、體脂率、去脂體重、身高）、寫三種、兩個授權時機、拒絕時的手打路徑。
  4. 三個畫面：境界、功法（含單一功法走勢）、錄入（今天的修煉清單、體組成表單、設定）。
  5. 慶祝與觸覺：全螢幕、粒子、震動、五選一與四選一的判定。
  6. 小工具：主畫面小、中，鎖定畫面圓形；跟主 app 共用資料。
  7. Siri 與捷徑：記修煉、問境界。
  8. 提醒：每月本機通知。
  9. 自動編譯管線：GitHub Actions 跑測試、簽章、建置、上傳 TestFlight。
  10. 網頁版補一顆「匯出 JSON」鈕。
  11. 上架素材：隱私政策頁、截圖、說明文字、隱私標籤。
- **🧠 深模組（核心邏輯密度高、要特別小心、別讓 AI 自己跑完不看）**：
  - 規則引擎（第 1 塊）。刪掉它攤進畫面，每個畫面都要自己算境界、功法、宗門，複雜度集中爆炸。保護方法：第一片就做它，配單元測試，拿網頁版真實資料當標準答案，兩邊算出來要一模一樣。
  - 慶祝判定（第 5 塊的判定部分）。它決定什麼時候放煙火，是 app 的靈魂；加了「精進要 1RM 真的變高」和「補登不放煙火」兩條新規則，容易寫錯。全部路徑列黃金行為。
  - 資料層的匯入與從健康 app 重建（第 2 塊）。匯入要把網頁版 JSON 的欄位一對一對映；重建要處理同一天多筆、來源混雜；寫錯會靜默掉資料。
  - 健康 app 連接層（第 3 塊）。對外系統、權限組合多（讀允許寫拒絕、全拒、之後在設定改）。
  - 自動編譯管線（第 9 塊）。憑證、簽章一次設好之後很少動，但壞了整條線停擺，而且在 Windows 上驗不了。
- **🧱 現成、不該重造的**：
  - 網頁版的三張表與公式數字（REALMS、MOVES、RANKS、FFMI 身高校正、Epley 1RM）。原樣搬，不「改良」。
  - 立繪 r0 到 r6、長老圖、圖示。轉成 PNG 放進 app，不重畫。
  - 網頁版的配色與版面：玉綠、金丹金、墨色紙底，深色模式那組色。照抄成設計代號。
  - 字體：LXGW 文楷 TC（開源授權）內嵌當顯示字體；內文用系統字。
  - Apple 原生框架：SwiftData、HealthKit、WidgetKit、App Intents、UserNotifications、觸覺回饋。不裝第三方套件、不用 CloudKit。

## 4. 測試決策

- **一定要能親手驗的行為**：S1 到 S27 每條的完成定義，由你在 TestFlight 版上親手跑。最要盯的：同一筆資料兩邊算出來的境界、FFMI、功法等級一模一樣（S4、S16、S22）；慶祝的每一條路（S5、S6、S12、S13、S14）加「補登不放煙火」「減重不放精進」兩條反例；體脂超過 20% 的軟化顯示（S7）；Siri 兩句（S17、S18）；小工具記完就更新（S19）；換手機（S21）；匯入舊 JSON（S22）；存檔失敗要報錯（S24）；刪除全部紀錄（S28）。
- **機器驗**：規則引擎做成純 Swift 套件，單元測試用網頁版匯出的真實資料當黃金集，GitHub Actions 每次推送都跑，紅燈不准建置 app。
- **我自己驗不了、要標記給 health-check 的**：從健康 app 重建量測時同一天多筆、來源混雜的邊界；健康 app 授權狀態的全部組合；自動編譯的憑證一年後到期；App Store 審核結果；小工具的系統刷新限制在舊手機上的表現。
- **黑箱盲點（誠實列）**：這台 Windows 跑不了模擬器。你指定用 Limrun（2026-11-07）：GitHub 建置時多產一個模擬器版上傳 Limrun，AI 透過它的遠端 MCP 開雲端 iPhone 模擬器，自己截圖、點按、讀元件樹，對標準清單逐條驗過才輪到你裝 TestFlight；一次自驗控制在十分鐘內（模擬器每分鐘 2 點）。模擬器仍驗不到：震動手感、Siri 語音（可用捷徑 app 觸發意圖代替）、真體脂秤同步、TestFlight 安裝流程本身，這四樣只能你真機驗。AI 寫的 Swift 第一次一定有編譯錯誤，要靠建置紀錄來回修，一次循環約 10 到 15 分鐘。

## 鎖定

此 PRD 為終點基準。AI 任何產出不得偏離；要偏離先回來改這份並經使用者確認。
