# 分析頁審查紀錄

## 2026-11-21｜第一次審查（照 analytics-book v2.0）

看了：`ios/Rencan/Views/Analysis` 七個檔、`Views/Gong` 八個檔、`RencanCore` 的 Digest、Formulas、Records、Sect、Reminder、三個 SwiftData 模型、境界頁、記一筆表單、小工具、通知。

沒看：真機截圖、TestFlight 上除了你還有誰在用、最近幾週有沒有人在記。所以第 0 層（紀錄還在嗎）這次查不了。

### 結論

要重新規劃，但不用整頁打掉。三個理由：

1. 這一頁照資料來源分段：體組成一段叫境界，訓練一段叫功法。書把這種分法列為死法 11（從資料庫欄位反推問題）。十個區塊裡，看完會讓下一次訓練不一樣的只有一個，功法卡上那句「再加 N 公斤升大成」。
2. 書說最常被讀的是一眼層和操作畫面，自己點進去的細查層最少人看。人蔘修煉的一眼層（境界頁、小工具、記一筆的預覽、突破慶祝）已經有了，分析分頁卻佔分頁列中間那格，裡面兩塊跟境界頁重複（宗門、現在的境界），兩塊是規則說明。
3. 沒有回顧層。這個 app 天然的回顧時刻是每月量測那天，現在量完只看到境界有沒有動，沒有「這個月練了幾天、哪幾門有進步、肌肉和脂肪各變多少」。

突破紀錄、天梯、宗門這三塊是留念用的，書的閘門 0 說留念型要換一把尺量。這件事要你決定，寫在最後一節。

### 四、待驗清單（我不能替你判）

- 雷達圖讀不讀得出「哪一門最弱」：找五個沒看過的人，五秒後問。對照組用橫條。
- 「再加 12 公斤升大成」他會理解成什麼：讀句題。
- FFMI 走勢看得出「有在長」嗎：讀圖題。
- 體脂秤一次量測的起伏會不會跨過一期：要查出處（`domi-evidence-hunter`），再決定 B2。
- B1 的次數上限訂幾下：同樣要查出處。
- 改完之後行為有沒有變：需要試用的人和對照組。現在如果只有你在用，這一關驗不了，只能當故事。

### 六、要你決定的四件事

1. 閘門 0：這一頁是幫他改變，還是幫他留念？ 核心動詞是「看見」，突破紀錄、天梯、宗門都偏留念。我的建議是拆開：留念的三塊留在分析分頁，用「看完有什麼感覺、想不想分享」來量；跟訓練決定有關的搬到量測日回顧和記一筆表單。
2. 境界會不會掉（B2）❓ 書的保守立場是不做會掉級的等級。境界會掉是你的遊戲設計，改了會動到核心玩法。
3. 雷達圖留不留（D2）❓ 先做讀圖測試再決定也可以。
4. 修煉卡分享。 書沒挖過「給別人看」這一塊（5-1 記為邊界）。只推得出兩個風險：被看見的數字會被往好看的方向推，被看見會碰到面子。現在的修煉卡先不動，之後要加排行或互看進度，先回書挖成一章。
