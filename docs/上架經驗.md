# 上架經驗（人蔘修煉 1.0，2026-11-18 送審）

這份記的是第一次把人蔘修煉送進 App Store 審核時，哪些事程式做得到、哪些只能在網頁上點，以及踩到的坑。下一個 app 上架前先讀一遍。

工具都在這個 repo：
- `.github/workflows/asc.yml`：手動觸發、只准 main。check 只讀；fill 填文字與設定；media 傳截圖與錄影；submit 選建置、送審。
- `ios/ci/asc_release.mjs`（check）、`ios/ci/asc_publish.mjs`（fill、media、submit）、`ios/ci/asc_listing.json`（要填的資料）。
- `.github/workflows/iap.yml` 加 `ios/ci/iap_products.mjs`：建內購商品、填名稱描述價格、傳審核截圖。
- `.vibe/tools/limrun_store.mjs`：在 Limrun 拍商品頁原圖、錄送審影片。
- `.vibe/tools/store_shots.py`：照茄記的準則把原圖合成商品頁截圖。

## 一、API 做得到的

全部用 App Store Connect API 金鑰從 GitHub Actions 跑，金鑰放在 secrets，跑完就刪。

- app 資訊：副標、隱私政策網址、主次類別、內容版權聲明。
- 年齡分級：整份問卷用 PATCH 一次填。Apple 會加新題目，2026-11 多了 `socialMedia`，沒給就回 409 並寫出缺哪一欄，照著補就好。
- 版本：版權、描述、關鍵字、支援網址、宣傳文字。
- 審核資料：聯絡人、備註、要不要示範帳號。聯絡人的姓名電話信箱放 GitHub secret `REVIEW_CONTACT_JSON`，repo 是公開的，不能寫進檔案。
- 價格：免費也要設，找台灣價位表裡 0 元那一格。
- 上架地區：`/v2/appAvailabilities`，一次給全部地區。
- 商品頁截圖：`APP_IPHONE_67` 這一格收 1320×2868。上傳是三步：先登記檔名大小、照 Apple 給的切片 PUT、再回報 MD5。
- 送審錄影：當成審核資料的附件傳（`appStoreReviewAttachments`），7 MB 的 mp4 沒問題。
- 內購：建商品、中文名稱與描述、價格、地區、審核截圖。傳完審核截圖，狀態就從「缺少資料」變成「可以送審」。
- 選建置、建送審單、把版本放進送審單。

## 二、只能在網頁上做的

這幾樣沒有 API，要登入 App Store Connect 網頁填。我不能代輸入 Apple ID 密碼，所以要多米登入，登入後才由我接手點。

- App 隱私問卷：選「不收集資料」，再按「發佈」，會跳一個確認視窗。
- 受監管醫療器材聲明：類別選「健康與健身」或「醫藥」就一定要填，在「App 合規資訊」頁。人蔘修煉選「不是」。
- 中國大陸的兩份合規表（安全性評估、AI 生成內容）：要附中國主管機關的文件，中國大陸上架也要 ICP 備案。我們的做法是把中國大陸從上架地區拿掉，這兩份就不用填，其他 174 區照常上架。
- 第一批非消耗性內購：Apple 規定要跟 app 版本一起送，API 回 `FIRST_NON_CONSUMABLE_MUST_BE_SUBMITTED_ON_VERSION`。做法是先用 API 把版本放進送審單，再到每個內購頁按「新增以供審查」，選那份送審草稿，十二個都加完才按「提交以供審查」。
- 付費 App 協議：在「商務」頁，要多米自己簽、填稅務和銀行。

## 三、順序

1. 先跑 check，看缺哪些欄位。
2. fill，再 check 一次。
3. 內購的審核截圖、商品頁截圖、送審錄影（iap screenshots、media）。
4. 網頁上：App 隱私、醫療器材聲明、上架地區（要不要中國大陸）、付費 App 協議。
5. submit：版本進送審單。
6. 網頁上：十二個內購各按「新增以供審查」，再按「提交以供審查」。

版本一進送審單，狀態就變成 READY_FOR_REVIEW，API 改不了版本頁的任何欄位。要改先把送審單撤掉。

## 四、踩到的坑

- 描述不收「▌」這個字，回 409。程式抽描述時把段落小標換成【】。
- API 的錯誤訊息很長，原因在 `associatedErrors` 裡。印 500 字會被切掉、看不到原因，現在印 3000 字。
- 送審前要確認隱私政策網址打得開。domyweb.org 上原本沒有這頁，是從 `E:\domyweb-main` 補 `/rencan/privacy/`、`/rencan/support/` 再推 main 部署的。
- 工具或文件 commit 推 main 一律帶 `[skip ci]`，不然每推一次就多一個 TestFlight 版本。在別的分支工作時，用 `git commit-tree` 直接在 main 上加 commit，不用切分支。
- 推同一條工作分支會取消那條分支正在跑的檢查線（concurrency），推之前先看有沒有在跑。

## 五、Limrun 拍照與錄影

- 本機金鑰在 `~/.lim/config.yaml`，2026-11-18 可以用，一趟 4.5 分鐘。
- 模擬器版用檢查線的 artifact `rencan-sim-app`（Debug 版），才吃得到 `-rencanUITest`、`-rencanSeed demo`、`-rencanOwn`、`-rencanStyle` 這些啟動參數。
- 截圖用 `screenshot({ format: "png", size: "full" })`，拿到 1206×2622。狀態列先用 `simctl status_bar ... --time 9:41` 固定。
- 錄影：`client.startRecording({ quality: 7 })`、`client.stopRecording({ localPath })`。原檔 844×1834、兩分鐘約 50 MB，用 ffmpeg 縮到寬 640、crf 26，剩 7 MB。
- `tapElement({ AXLabelContains: "購買" })` 會同時對到購買鍵和「恢復購買」而失敗，要用更長的字（「購買「」）。
- 測試模式不碰健康 app，設定頁會寫「這台裝置沒有健康 app」，這句不能出現在商品頁截圖，拍的時候捲過去或裁掉。

## 六、內建瀏覽器

- 面板藏在背景時，App Store Connect 的頁面不會畫出來，點不到東西。要請多米點視窗右上角的地球圖示把面板打開。
- 面板很窄時先把畫面設成 1280×900，網頁版面才不會擠成手機版。
- 每個內購頁的按鈕位置都一樣，用 `find` 找「新增以供審查」和「iOS 提交項目草稿」比用座標點穩。
- 改上架地區這種動作，權限系統會擋下來要多米本人同意，先講清楚為什麼要改再請他按。

## 七、還沒驗證的

- 1.0（34）2026-11-23 被退，只有 Guideline 1.4.1：健康計算沒有附出處連結，點名「輸入體組成」。做法是加「計算依據與出處」頁，入口放在那張表單的欄位正下方，另外分析頁兩張說明卡、設定的關於也放。下一個有健康計算的 app（BMI、FFMI、熱量、1RM），第一版就要有這一頁。
- 寫出處之前要先核對數字。這次發現 FFMI 身高校正用 6.1，Kouri 1995 原文是 6.3；「體脂偏低」和「比較準」兩句找不到出處就拿掉。PubMed 網頁會擋程式抓，改讀 `eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=pubmed&id=編號&rettype=abstract&retmode=text`。
- 重送的做法（2026-11-24）：`asc.yml` 跑 `prepare` 換建置和備註，再到網頁的送審單發回覆、版本頁按「更新審查內容」、送審單按「重新提交至 App 審查」。回覆審查沒有 API，只能網頁。內購留在原本的送審單裡不用重掛，API 上顯示 READY_TO_SUBMIT 是正常的。`fill` 和 `submit` 都不適合重送。
- 1.0（40）2026-11-26 被退，Guideline 2.3.7：商店截圖寫了價格。「免費」「付費造型」都算，不只是金額。上次（1.4.1）沒被點到，第二輪才點。截圖一律不寫免費、付費、價格；要講就寫在描述，退件信自己這樣建議。只換截圖不用新建置。
- 真的 App Store 購買（不是模擬器的假商店）要在 TestFlight 用沙盒帳號買一次才算驗過。
